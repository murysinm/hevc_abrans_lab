# Лабораторная работа: оптимизация энтропийного кодирования в кодеке H.265

## Требования

Лабораторная работа рассчитана на то, что она будет выполняться на Linux. Скрипты профилирования используют `perf`, `taskset` и управление частотой CPU через sysfs, поэтому на Windows они не работают. Выполнение на Windows теоретически возможно, но в таком случае студент должен самостоятельно разобраться со сборкой кодера и декодера, а также реализовать аналог `profile-decode.sh` для Windows.

## Базовая реализация

В данной работе рассматривается кодек H.265/HEVC, в котором стандартный модуль энтропийного кодирования CABAC заменён на алгоритм адаптивного двоичного rANS (ABrANS). Реализации экспериментальные, корректно работают только в однопоточном режиме.

Работа состоит из двух компонентов:

- **[x265_abrans]**: кодер H.265 с ABrANS вместо CABAC.
- **[ffmpeg_abrans]**: декодер H.265 с ABrANS вместо CABAC (минимальная сборка FFmpeg).

### Принцип работы ABrANS

Описание алгоритма ABrANS приведено в статье [1].

В кодек встроена модифицированная версия ABrANS: кодер и декодер поддерживают множество вероятностных моделей.

### Где смотреть код

**x265_abrans:**

- `source/encoder/entropy.cpp` - основная часть энтропийного кодера. В рамках данной работы нам интересен в основном этот файл.

**ffmpeg_abrans:**

Из всего ffmpeg нам потребуется только библиотека libavcodec. Из неё основной интерес представляет файл `libavcodec/cabac_functions.h`, ознакомление можно начать с него.

### Результаты базовой реализации

Измерения проводились на двух наборах видеопоследовательностей (см. раздел «Датасет»). Кодирование - при значениях QP 22, 27, 32, 37, параметры `--no-wpp -F 1 --frame-threads 1`. Декодирование прозводилось в однопоточном режиме (`-threads 1`). Сложность измерялась в тактах процессора (медиана по 10 прогонам, фиксированная частота CPU, `taskset` на отдельное ядро). Знак «−» означает улучшение относительно стандартного CABAC.

**CIF/QCIF, среднее по 10 последовательностям:**

| QP | Δ размера потока | Δ скорости декодирования |
|----|-----------------|--------------------------|
| 22 | +0.33 % | −4.23 % |
| 27 | +1.04 % | −2.70 % |
| 32 | +4.05 % | −0.57 % |
| 37 | +10.31 % | +0.43 % |

**1080p, среднее по 3 последовательностям:**

| QP | Δ размера потока | Δ скорости декодирования |
|----|-----------------|--------------------------|
| 22 | −0.44 % | −4.05 % |
| 27 | −0.35 % | −2.63 % |
| 32 | −0.26 % | −1.26 % |
| 37 | −0.18 % | −0.53 % |

На последовательностях 1080p ABrANS превосходит CABAC одновременно по размеру потока и скорости декодирования при всех QP. На CIF/QCIF в предложенной реализации при высоком QP наблюдается ухудшение компрессии, которое нейтрализует выигрыш в скорости.

## Задание

Улучшить базовую реализацию ABrANS так, чтобы исключить проигрыш по скорости декодирования на CIF видеопоследовательностях. В базовой реализации проигрыш в скорости из-за того, что имеет место большой проигрыш по размеру закодированного потока.

### Возможные направления

- При кодировании динамически высчитывать (например, перебором) оптимальный размер VSW (Virtual Sliding Window) и сохранять в закодированном файле;
- Для каждого из контекстов подобрать оптимальный размер окна предпосчётом. При кодировании/декодировании конкретного контекста использовать предподсчитанный размер окна.

## Инструкция по запуску

### 1. Сборка

Смотреть инструкции в репозиториях.

### 2. Кодирование

```bash
./compare-x265.sh \
    /path/to/x265_abrans_base \
    /path/to/x265_abrans_modified \
    ./test_data \
    "--no-wpp -F 1 --frame-threads 1" \
    "22 27 32 37"
```

`test_data` - папка с видеопоследовательностями формата y4m.

Результаты сохранятся в `./test_data/x265-compare/{old,new}/qp<N>/`.

### 3. Профилирование декодирования

Обратите внимание, что скрипт запускается под sudo.

```bash
sudo ./profile-decode.sh \
    /path/to/ffmpeg_abrans_base \
    /path/to/ffmpeg_abrans_modified \
    ./test_data \
    10
```

Итоговая таблица: `./test_data/profile-results/summary.csv`.
